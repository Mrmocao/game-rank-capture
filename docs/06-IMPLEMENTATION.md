# 06 技术实施与交付阶段

## 1. 技术基线（建议，不是版本时效声明）
后台Java，数据库MySQL为已确认要求。新项目建议Java21、Spring Boot3.x、MySQL8、Flyway、Maven；具体补丁版本由Codex初始化时依据官方兼容说明确定并锁定。
前端建议Vue3+TypeScript+Element Plus+Vite，以匹配锦鲤后台；如果公司已有成熟栈优先复用，不因原型原生JS而限制生产选型。
默认模块化单体：web/api、application、domain、infrastructure；采集任务可以同仓独立进程，不首期拆微服务。
数据库访问MyBatis或JPA二选一并记录；不同时引入多套。首期可用数据库锁/任务表+Spring调度，不强制Redis、Kafka或分布式任务平台。
对象存储接口独立，开发环境可本地目录、生产用已有存储。AI供应商通过接口适配，不绑定某个模型。

## 2. 模块边界
- catalog：产品/平台版本/身份关联/人工覆盖。
- ranking：榜单定义、快照、历史、变化和缺失状态。
- collection：来源适配器、调度、运行记录、原始材料和AI提取。
- curation：IAA证据策略、市场规则、入库状态。
- selection：简单填报与并发控制。
- reporting：候选选择、冻结快照、AI文案、历史导出。
- admin：配置、权限、审计，不与制作记录混成流程引擎。

## 3. 阶段与完成标准
### P0 来源验证与设计校验
读完交接包，建立需求追踪矩阵；核实企业现有前端/登录环境。产出来源能力表、脱敏真实样本、字段映射和明确阻塞。未验证来源允许stub，不伪造可用性。检查DDL/API与需求差异并记录。
### P1 工程与产品库
Java/MySQL/前端骨架、迁移、最小鉴权、产品/版本分层、跨平台聚合、按日快照查询、详情、多人选用、导出、二级菜单。全部使用可重复seed并标注演示数据。
### P2 真实采集闭环
先打通一个已验证源的真实chart：原始材料→解析/AI→校验→快照→页面。必须证明重复任务幂等、来源失败无伪数据。再按相同契约接其余平台；未接来源明确未覆盖。
### P3 证据与规则
版本IAA、证据历史、规则版本/试算/发布、自动入库、人工覆盖、关联/撤销。测试同产品不同版本变现冲突、历史状态和缺失数据。
### P4 周报与运行交付
精选去重、观察提醒、已制作动态、冻结与版本、导出、调度和异常；真实试运行完整每日周期。交付启动文档、配置模板、数据恢复和限制说明。

### 当前核心周报口径（新增确认）

用户核心目标为每周国内最多 5 款、海外最多 5 款。候选由 Java 确定性筛选：已发布榜单快照、平台版本级 `PURE_IAA` 证据、排名和覆盖状态；同一产品跨平台去重。每条精选冻结 `snapshot_id`、业务日、平台、地区、榜单原名、名次、完整性、IAA 结论和证据引用，理由说明数据缺口。AI 只负责玩法标签、证据定位和文案，不得修改候选集合或数字。候选不足时输出实际数量和覆盖原因。
阶段推进无需反复询问已确认需求；涉及购买、真实部署凭据或不可逆操作时单独处理。不要把每阶段结束都变成等待批准的流程。

## 4. 运行与配置
配置样例只用占位符：DB_URL/DB_USERNAME/DB_PASSWORD、AI_BASE_URL/AI_MODEL/AI_API_KEY、SOURCE_*_SECRET_REF、OBJECT_STORE_*、BUSINESS_TIMEZONE。
生产密钥不进前端、日志、样本和Git。对接公司登录前，开发环境演示身份必须受显式dev profile控制，不可无鉴权暴露生产。
启动说明覆盖：先迁移→seed仅dev→启动Java→前端→任务手动dry-run→接入真实源→启用daily/weekly；真实模式与模拟模式隔离。
原型Sites托管用于设计演示，不是Java/MySQL运行环境；实际部署公司服务器/容器环境，地址和权限待提供。

## 5. 质量与运维
单元测试聚焦规则/日期/IAA、集成测试聚焦唯一键/事务/历史/并发，E2E验证主要旅程。冻结时钟覆盖跨时区周边界。不要只测页面能打开。
任务心跳、失败分类、运行计数、采集滞后、覆盖率、AI费用、周报状态可观测。日志带requestId/runId，不带敏感材料全文。
迁移上线前备份与测试恢复；回滚应用保持数据库兼容；不自动删除旧快照。不把付费来源素材同步到公开演示站。

## 6. 每阶段Codex交付格式
完成的需求ID/文件与迁移、启动方式、实际运行的检查结果、未完成项/真实来源缺口、下一阶段动作。区分“已实现”“样本验证”“真实接入验证”“生产运行”。
