# 新机会优先：上线门槛与市场分类档案

日期：2026-11-16。来源筛选2.5.0，精选Skill2.8.0，正式资格引擎仍2.2.0；Flyway V25。部署状态和实测结果见[验收](acceptance/2026-11-16-taxonomy-launch-gate.md)。

## 目标与规则

精选优先用于研究新类型、新题材、玩法差异和早期机会；老游戏留作市场参照，不凭热门排名反复推荐。当前1/2/2（20%/40%/40%）是最多5项的目标配额，证据不足留空。

|情况|当前执行行为|边界|
|---|---|---|
|来源上架距截止日满730天|标记LEGACY_EXCLUDED，不占任何精选席，保留候选审计和榜单历史|730天为本次建议默认门槛，约两年，不是游戏必然衰退的结论|
|日期已知且未满730天|继续执行原有连续榜单、身份、玩法、付费风险与配额门槛|不自动认定为新游戏或新玩法|
|日期未知、非法或晚于报告截止日|来源链需28日内至少14个实际观察日；仅可进入基准或待核研究补位，不进入新入榜/加速席|不是经过14天就自动放行，缺采日不计数；正式候选链读取已有14日窗口，要求14个实际观察日|

正式候选与来源研究均执行门槛。当前没有老游戏人工例外入口。首次观察、首次进入Top100、来源称为新游、平台上架与全球首发分别表达，不互相替代。规则不修改旧周报；显式重新生成依照每周一份规则覆盖所选周，其他周保持原样。

## 日期与证据

读取来源字段`releaseDateRaw`（现行Apple适配器）、`releaseDate`、`release_date`、`firstReleaseDate`、`first_release_date`、`sourceReleaseDate`。Apple商店日期只称为“来源上架日期”；没有证据不能称为全球首发或小游戏首发。日期连同来源URL、业务日、观察ID、材料SHA256冻结。日期格式非法或未来日期不转换成0天。

冻结字段：launchDate、launchDateBasis、launchDateEvidence、launchDateStatus、launchAgeStatus、launchAgeDays、launchGatePassed、requiredObservationDays、launchDateGap、longObservationDays、longObservationEvidence。7日趋势与28日实际观察计数分别展示。

实际生产材料回放：iOS来源ID995122577（地铁跑酷）的来源上架日期2017-01-22；1470558945的来源上架日期2019-07-02，两者均被新规则排除。此处为真实材料重算，不是新采集或全球首发核实。

## 市场分类档案

入口：市场洞察 → 玩法与赛道。

- GENRE 游戏类型：例如跑酷、消除；定义包含和排除边界。
- THEME 题材：例如烹饪、末日；与类型分开。
- MECHANIC 核心机制：描述核心操作和循环，避免只填泛化标签。

普通表单建立词条、选择词条、登记来源与摘录，直接查看最近200条证据，无需填写JSON。关联范围为统一产品、平台版本或市场样本。服务端校验产品/版本从属、词条工作区、日期、长度、链接和市场。重复证据幂等，原始关联追加留存。数据是待复核材料，当前不提供审核/撤销界面，也不计算全市场拥挤度或创新评分。

新周报按知识截止和业务截止读取已关联分类证据；产品级仅匹配已确认统一产品，版本级仅匹配平台+稳定外部ID及适用市场，未关联市场样本不复制给同名游戏。关联证据进入研究卡、冻结周报和新生成的研发HTML交付包。它不能自动创建正式产品、证明IAA或增加推荐分数。

## 接口与迁移

- GET `/api/v1/market-taxonomy?date=YYYY-MM-DD`：当前已知、观察日不晚于所选日的词条及证据计数，不是历史知识回放。
- POST `/api/v1/market-taxonomy/terms`：建立或定位词条（termType、canonicalName、definition、actor）。
- GET `/api/v1/market-taxonomy/terms/{id}/observations?date=...`：证据详情。
- POST `/api/v1/market-taxonomy/terms/{id}/observations`：登记带来源的分类依据。

V25创建market_taxonomy_term、market_taxonomy_observation两表，所有表/列有中文注释；参考DDL同步。应用通过Flyway/JDBC迁移，无新增环境参数，不需要MySQL CLI或Docker。
