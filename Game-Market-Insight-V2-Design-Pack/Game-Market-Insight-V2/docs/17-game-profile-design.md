# V2.3 游戏情报档案：产品与交互设计

版本：2.3.0；日期：2026-10-30。此次升级产品库与单款游戏信息，不更改V2.2精选公式。全部原型内容为虚构演示，真实采集、AI调用、Java及MySQL接入未实现。

## 1. 要解决的问题

榜单回答“在哪里、何时表现如何”，单款档案进一步回答“是什么、为何吸引玩家、怎样变现、哪里存在机会、团队如何验证”。使用者从榜单或产品库进入同一款产品的完整档案，再决定补证、选用或继续观察。

产品库保留全量研究对象；只有目标版本具备纯IAA依据才进入正式IAA候选。混合变现、未知、冲突、过期样例可以研究，不能因排名靠前或资料多被标成合格。

## 2. 三层资料，逐步补齐

| 信息层 | 目标 | 触发时机 | 不足时的行为 |
| --- | --- | --- | --- |
| 基础档案 | 识别产品、查看商店和榜单轨迹 | 首次发现后建立最小记录 | 不阻塞研究池记录；身份不明不能正式推荐 |
| 深度情报 | 理解玩法、体验、玩家声音和竞品 | 有市场信号、人工关注或进入周报候选 | 保留缺口，AI可给待验证假设 |
| 精选依据 | 确认IAA、制作条件和内部验证结果 | 正式入库、精选或选用前 | 资格与推荐分层分别处理，按14章容错方案输出行动 |

采集目录仍使用第02章120个原子指标；本章81个界面字段是围绕单款游戏的展示投影，允许聚合多个原子指标。不能宣称81字段覆盖或替代全部120指标，也不能把字段数当采集完成数。截图、视频和证据附件使用关联资源，不塞进一个长文本字段。

## 3. 十二个信息域

| 信息域 | 应展示的内容 | 帮助使用者判断 |
| --- | --- | --- |
| 基础身份（9） | 名称/别名、平台ID、开发/发行主体、市场、语言、商店及试玩入口 | 是否同款、哪个平台版本、从哪里核验 |
| 商店与版本（9） | 官方简介、分类、上线日、首次观察、版本/更新日期/说明、包体和设备要求 | 新品还是老品翻红、变更是否影响结论 |
| 核心玩法（8） | 简述、核心循环、操作、胜负、单局时长、关卡、外围成长、受众假设 | 好玩机制与可验证的玩法需求 |
| 美术与体验（6） | 风格、2D/3D、横竖屏、动效、联网、性能 | 表现成本、设备和体验约束 |
| 广告与变现（7） | 模式、广告形式、触发奖励、观察频次、内购及排除内购依据、资格范围 | 目标版本能否作为纯IAA参考 |
| 市场表现（6） | 榜单状态、当前/历史最佳名次、有数据采样日、下载/活跃估计 | 需求表现与持续性，保留未知 |
| 玩家评价（6） | 来源评分/评分数/评论数、样本范围、喜欢点、槽点 | 热度背后的体验反馈及其分母 |
| 舆情与传播（6） | 提及量、同口径增量、搜索、创作者、事件、独立来源性 | 自然传播、争议、转载或商业内容 |
| 广告素材与投放（6） | 素材入口、前段吸引点、创意变体、观察窗口、地区渠道、与实机一致性 | 买量表达与实际体验是否匹配 |
| 同类竞争（6） | 玩法家族、竞品、同类供给、差异、衰退案例、体验缺口 | 赛道拥挤程度和可改善的方向 |
| 制作适配与机会（6） | 最小原型、工作拆分、依赖、人日区间、实验假设、停止条件 | 当前团队是否具备验证条件 |
| 内部选用与验证（6） | 多人选用、测试计划、实际成本、留存、经济性、验证结论 | 形成自身证据与失败经验 |

字段的完整键、类型、优先级与AI用途见17-profile-fields.csv。所有可读资料均区分来源事实、供应商估计、计算指标、AI分析草案、人工核查。

## 4. 产品库改版

表格展示：游戏名/玩法简述 → 各平台独立排名 → 变现依据与参考平台 → 有资料项/适用项/AI草案/待补项 → 查看档案与选用。

筛选：关键词、平台、地区、IAA有依据/待核查/混合变现、资料缺口/冲突失效、截至日期。排序支持首次发现日期或指定平台地区的单榜名次。未指定单榜范围时，不进行跨平台排名平均或排名排序。

全部平台视图每行明确“参考平台”；列表资格、资料量均针对该参考版本。点击其他平台名次直接进入相应版本，不能沿用首版本的IAA结论。生产版宜提供“所有平台版本展开”，而非含糊地显示整款产品纯IAA。

当某日未采集榜单时，保留截至该日已知的产品档案，名次显示“无快照”。首次发现前不展示已有市场资料；实际上线日与系统首次观察日始终分开。

## 5. 完整详情页

页头固定表达产品、玩法、虚构/正式数据标识、目标平台市场、知识截止日、应用版本和变现资格。操作包括导出档案、生成补全任务、选用/添加记录。

四张摘要卡：当日独立榜单、当前可读资料、评价样本、待补资料。资料量是展示完整性指标，不是数据置信度、机会分或爆款概率。AI草案计入可读项时必须并列显示其数量。

| 分区 | 主要内容 | 关键交互 |
| --- | --- | --- |
| 档案概览 | 基础与商店资料、媒体入口、12域资料地图、下一步研究 | 点资料地图进入对应区；查看字段依据 |
| 玩法与体验 | 核心循环、体验与表现、实机材料 | 每个结论可回看来源；非实机示意明确标识 |
| 市场表现 | 单榜历史、采样日、规模指标、覆盖状态 | 只画截止日前数据；缺失位置不补0、不补前值 |
| 玩家声音 | 样本规模/范围、情感与主题、示例摘录、舆情事件 | 评分数、评论数、采样评论数分别展示 |
| 广告与变现 | IAA依据、广告触发、频次、素材与投放 | 依据冲突或新版变化触发复核；买量不替代玩家热度 |
| 竞品与制作 | 玩法家族、同类关联、原型范围、人日/依赖、测试与停止条件 | 竞品为关联记录，不自动合并；成本标人工估计 |
| 证据与补全 | 字段证据、补全任务、待复核材料三个子页 | 按字段/状态筛选、历史回放、生成/去重任务、补材料 |
| 选用记录 | 多人独立认领、负责人、参考版本、进度及结果 | 新建和编辑；当前协作状态不随历史市场日期回退 |

返回列表保留会话内筛选；详情链接携带product、version、date、tab，可刷新或用浏览器后退。从榜单进入优先选择榜单的对应平台市场。默认不是跨平台综合详情。

## 6. 范围、时间与失效

每条关键资料绑定产品、平台实体、市场、语言、适用应用版本、观察窗口和知识可用时间。默认“截至日期”按研究方案时区截日；原型以日粒度演示。

历史回放只能使用observed_at和available_at均不晚于截止日的记录。旧日期不展示后来形成的分析或后补结论。重算历史时须明确区分“当时知道什么”与“今天修订后的历史”，默认采用前者。

版本绑定的资料在应用更新后进入需复核状态，保留旧记录但不将其显示为当前事实。证据有效期过后同样处理。对不受版本变化影响的主体资料可使用独立有效期。

| 状态 | 界面 | 计算与任务 |
| --- | --- | --- |
| available | 有资料，显示类型与时间 | 可按规则使用；AI草案不能代替资格证据 |
| missing | 未采集 | null，生成补充任务 |
| not_authorized | 权限受限 | null，评估授权/采购/替代来源 |
| not_supported | 来源不支持该口径 | null，评估可比替代；不反复重试同接口 |
| not_yet_known | 当时未形成 | null；不显示未来材料 |
| stale | 需重新核查 | 当前值null；旧值可在历史中查看 |
| conflict | 证据冲突 | 当前结论暂停，保留双方材料与待裁决项 |
| not_applicable | 不适用 | 需原因；移出资料量分母，不凭空加分 |

数值0只有被实际观察/计算得到才有效。缺失排名不等于榜外；完整Top100快照中确实未出现的情况，生产实现应使用out_of_monitored_range，而不是rank=101。原型档案仅演示有名次和缺失，不演示该完整榜外分支。

## 7. 媒体与证据交互

实机截图、试玩视频、广告素材分别建资源类型；记录平台版本、拍摄/发布/采集时间、来源、权限、片段定位与内容hash。广告素材不能冒充真实玩法画面。

有授权资源显示缩略图、放大或播放器；只有外链时显示“打开来源”；失效、无权限或未采集时显示明确状态和补充入口。原型只有代码绘制的流程示意，不伪造实机截图或视频；两个真实媒体入口均为待补状态。

字段依据弹窗展示当前状态、该字段截至日期的历史、观察/可用时间、适用版本、有效期和证据。生产来源失败时显示“无法回放”及可保留的信息，不能标成完整覆盖。

## 8. 补全与材料复核

用户点击“生成补全清单”，按当前目标版本的缺口形成任务。先补纯IAA资格、身份、玩法和制作依赖，再补佐证。同产品+版本+信息域存在待处理/处理中/待复核任务时不重复创建。

任务支持负责人、优先级、状态、过程结果；状态为待处理→处理中→待复核，或暂不可得。暂不可得需要原因和后续复查条件。任务完成不代表资料可信。生产系统可以拆分字段任务；原型按信息域分组。

手动材料提交要求字段、材料类型、提交人、观察日期、来源名称、摘录及可选链接。仅允许http/https来源链接。草稿进入独立待复核区，不改字段事实、不提升覆盖、不解除IAA门槛。

生产复核应检查对象/范围/时间/原文、重复性、矛盾与来源权限；形成新的FieldObservation或Claim并保留审计。AI可提取、分类、识别候选冲突、建议优先级；没有依据时输出未知并提出具体补证任务。材料里的指令不得影响采集器权限和业务规则。

## 9. 与每周精选的连接

档案只提供有来源的输入。正式评分使用14章版本化规则，分别输出资格、特征范围、推荐层级、理由、缺口和验证动作。不能把81项填充比例乘到机会分里，也不能用AI长篇文案提升数值。

榜单缺失但有合格替代需求证据，可按已声明协议进入条件推荐；IAA未知只能形成核查/研究建议，不能正式收录为纯IAA。玩家热度上涨而广告负面集中时保留事件约束。更多真实反证允许降低优先级，不能承诺资料越多分数越高。

当前V2.3档案10款夹具与V2.2精选18案例独立。界面保留清晰提示；生产开发完成统一身份和特征映射后才能自动衔接。

## 10. 来源可得性与实施顺序

先明确字段、口径、来源资格，再选采购和采集方式。商店页面可能提供名称、主体、描述、分类、截图、版本与来源展示评分；具体国家/字段可用性逐项验证。不能将某个平台自己的开发者数据接口当成全市场竞争产品数据接口。

官方参考：Apple产品页说明 https://developer.apple.com/app-store/product-page/ ；Apple Search/Lookup https://performance-partners.apple.com/search-api ；Google Play评论接口权限说明 https://developers.google.com/android-publisher/reply-to-reviews 。这些参考仅说明资料类别或授权边界，不代表本系统已接入或能批量获得所有对手评论。

实现顺序：统一身份与基础档案 → 指定范围和历史快照 → 人工材料/证据/补全 → 玩法与玩家声音 → 广告/竞品/制作分析 → 接入V2.2推荐和内部测试反馈。供应商选择、抓取频率及付费预算另行验证，不阻塞本轮产品设计。
