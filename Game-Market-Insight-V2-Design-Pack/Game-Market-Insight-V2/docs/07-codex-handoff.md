# 给 Codex 的开发交接

## 1. 请先理解本次交付

这是V2.2产品需求与交互原型，核心是信息范围和推荐判断。原型为静态HTML/CSS/JS，展示虚构数据，本地记录使用浏览器存储。正式系统按用户确定的Java+MySQL实现，当前没有后端、采集器、真实AI或自动周任务。

此包替代V1的产品范围、信息模型、推荐和页面定义；保留跨平台独立榜单、日期、两级菜单、多人选用等已确认约定。与V1技术文件冲突时按本包产品契约调整，不能直接执行旧建表脚本便声称V2完成。

## 2. 推荐开发顺序

1. 先读14、15、16了解V2.2容错，再读01、03、06；04为历史基线。先实现纯领域模型和数据契约：产品/版本/证据/指标/决策/报告/记录。
2. 实现测试夹具导入与查询、平台日期过滤、缺失态、证据浏览；优先能用人工结构化材料跑通研究流程。
3. 实现评价主题与聚合口径、去重关联、来源覆盖与版本；先确定性计算，再加AI结构化标注。
4. 实现资格规则、六维评分依据、研究方案版本、多样性、入选和未入选解释。
5. 实现周报冻结与修订、轻量选用记录、验证结果和审计。
6. 验证主流程后，再单独设计数据源验收与实际采集接入；不要先开发大批不稳定爬虫。

当前迭代完成标准：使用可追溯的结构化测试数据，能从信息→证据→候选→精选→选用→反馈完整运行；核心统计与未知状态正确，真实来源接入可后置。

## 3. 必须坚持的约束

- 资格按平台版本判断；统一产品只负责归集。同款iOS混变不能污染微信纯IAA结论，也不能借微信资格推荐iOS版本。
- 不平均跨平台榜单名次；买量证据和玩家需求不混算。按单榜统计变化，缺失不填101。
- 所有AI事实附引用；未知必须可表示，模型不能补造排名、下载、用户评价、收益和工期。
- 玩家评论、评分数、采集条数分别记录；观点抽样和覆盖变化不能悄悄改变统计分母。
- 推荐先硬门槛再排序；不能靠高分抵消IAA未知、重大身份冲突或不可验证证据。
- 当前权重及阈值都是可讨论初值，不称为训练出的成功预测模型。
- 生产多租户/账号、数据权限、服务端存储由后台实现；localStorage仅作为原型。
- 保留历史版本、未入选、负面结果和人工纠正，不只保存“成功项目”。

## 4. 模拟数据的使用

`contracts/demo-data.json`与在线原型的`data-v2.js`是同一虚构数据集：10款产品、60条手写示意摘录、4个榜单日期。聚合评论计数是独立夹具，不是60条摘录的统计结果。正式数据处理测试应另建完整可计算样本集合。

原型基础产品库已升级为V2.3完整档案；每周精选V2.2使用18个独立虚构测试案例；V2.1另保留历史测试集，数值由公开公式计算，事件/IAA等事实输入仍为模拟。开发应以14中的范围、分层和资格规则实现，并沿用04证据锚点的定义，不能把演示逻辑当成正式算法。正面样本少与重大舆情冲突须区分。

## 5. 文档中的开放设计参数

可继续调优但不阻塞产品评审：市场验证阈值、证据有效期、评价低样本阈值、周报类别覆盖目标、同玩法上限、团队成本预算、已推荐冷却周期、来源覆盖标准。先版本化配置，后用真实试验反馈校准。数据源供应商/预算/访问权尚未确认，不声称接口可得。

## 6. 交付验收

先执行08中的业务验收，再按团队工程规范做Java服务与数据库迁移检查。验证优先关注错误可能改变研究结论的边界：时间泄漏、重复证据、版本混淆、样本分母、非IAA误入、旧周报被修改。不要用大量只断言样式或重复实现的测试替代这些检查。


当前V2.2以14容错方案、15演算和16验证记录为准；04、11、13保留V2.1历史对照。V2.3产品浏览已改用范围明确的资料与资格；不再使用旧固定分。


## V2.2 首轮开发任务

1. 实现MissingState、FeatureRange、KnownConstraint、RecommendationAction及验证协议版本，先保存来源和缺失原因。
2. 将weekly-engine-v22.js的可复算规格迁至Java；使用contracts/weekly-v22-*三份JSON对齐18例与11种场景。原型依赖weekly-engine-v21.js的纯数学辅助函数，不能只复制单文件。
3. 实现缺失和冲突的范围计算、推荐层级、预算约束、保守/探索组合；不要采用V2.1完整输入门槛阻断所有推荐。
4. 实现坏记录隔离、同窗口有效证据复用、已知问题持续、无合格候选的行动报告、报告修订。
5. 用真实证据验证来源权限、替代需求协议、AI弃权与抽样口径；在接真实采集前，先以人工导入材料验证业务链。

本次没有实现真实预测模型、收益估计、缺失值学习插补或Java后端。初始规则可解释、可复算，但需要10规定的时间外验证。不要把虚构协议Q的passed=true和示例evidence字符串复制为生产资格校验。


## V2.3 单款档案覆盖条款

当前单款游戏信息设计以17、18、19章为准：12信息域、81展示字段、8分区，平台/市场/版本/截止时间独立；来源事实与AI草案分别保存。完整资料量不等于推荐分，缺失和新反证不能被填补文案掩盖。V2.2推荐公式与分层规则保持不变。
