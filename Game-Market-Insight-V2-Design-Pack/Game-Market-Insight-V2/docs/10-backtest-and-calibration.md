# 回测、校准与上线验证 V2.2

## 1. 必须回答的两类问题

问题A：能否更早找出需求后续仍成立的原产品。问题B：这些参考是否帮助团队低成本做出通过内部测试的自主产品。A的标签能覆盖多数候选；B只在真正开发/测试后出现，存在选择偏差。禁止把A的回测准确率宣传成B的爆款成功率。

## 2. 标签先登记，再看结果

| 标签 | 启动定义 | 不可观测时 |
| --- | --- | --- |
| 后续需求成立 | 推荐截止后28日，同榜有效观察≥21日且Top100日数≥14日 | 标签unknown；不得记失败 |
| 市场加速 | 后续窗口的榜单位置指数较推荐时提高，且覆盖可比 | 基期/后窗不足则unknown |
| 有效实验 | 事先定义的假设得到足够质量的可判定测试结论 | 未测、停工或样本不足分别记原因 |
| 原型适配 | 在预定范围/预算完成最小可玩验证 | 非技术原因停工不等同不可实现 |
| 内部产品通过 | 自有版本在预注册指标及样本条件下通过 | 只对已测试样本可评估 |

28/21/14是初始业务标签，不是自然规律；必须做14/28/56日等窗口敏感性分析。原作版本、市场和来源定义改变后不能强接成同一标签。事后修改通过线必须生成新标签版本，并保留旧口径结果。

## 3. 历史回放与防泄漏

每个历史周t冻结当时可得的所有候选，不只冻结最终选中者。按available_at过滤证据；采用当时生效的实体关系、标签、去重簇、来源范围和研究方案。禁用未来评论、后续排名、事后人工结论与如今已知的最终成功产品来修正过去分数。

示意时间线：前8周构造/训练，接4周验证调参，再留至少一个标签观察周期，随后4周作最终测试。只有标签在训练截止前已成熟的样本才能用于训练。这些周数是规划示例，不是数据量已足够的证明；数据少时延长影子运行，不进行复杂调参。

采用向前滚动多个切点，按周及玩法家族分组汇报。跨周反复出现同一产品并非新的独立试验，不允许简单当作扩大样本量。重叠的28日标签导致周间相关，区间估计需按适当时间块/产品家族做配对重采样，不能对每行独立抽样假装独立。

## 4. 基线与公平比较

固定候选范围、资格、截止时点、目标数量、同类上限和市场范围，再比较以下基线：B0最新单榜排名、B1过去14日在榜率、B2旧V2规则、B3六维等权、B4本版默认权重。另保留有序人工盲评作为参考，不当作经营真值。旧V2基线只有在当时输入和规则能够回放时才参与；无法回放标not_available，禁止事后用最新AI和未来资料编造旧分数。

分别做：同数据不同算法；同算法逐步增加评论/舆情/内部成本信息。后者的消融实验能回答哪个信息域带来增量价值。不得只展示表现最好的一个切点、玩法或市场。

## 5. 结果不完整时怎样计算

令L为实际推荐数量（不足目标时用实际数量），M为结局已知数量，S为其中成功数量。

```text
已知结局样本中的命中率 = S/M                   M=0时未知
结局覆盖率 = M/L
全部推荐的最坏边界 = S/L
全部推荐的最好边界 = (S + L - M)/L
```

例：推荐8款，6款后续结局可观察，4款需求成立。可观察样本命中率66.7%，覆盖率75%，全部推荐的可能范围50%～75%。这个范围是缺失标签的边界，不是置信区间。不能直接写“准确率66.7%”而省略覆盖。

用于算法比较时还需报告两方案共有且可观测的集合、独立发现集合及各自覆盖差异。目标K与实际填充率L/K分开；算法通过只推荐一款不能在不披露填充率时宣称显著优于8款方案。

## 6. 核心评估表

| 维度 | 指标 | 解决的问题 |
| --- | --- | --- |
| 事实可靠 | 资格误入率、引用可追溯率、人工改判率 | 是否把未知/混变或错误实体推荐出来 |
| 市场有效 | 已知结局命中率+覆盖+缺失边界、提前发现天数 | 是否优于只看榜单 |
| 组合有效 | 实际填充率、玩法覆盖、跨市场重复、换权重稳定度 | 是否提供有用且不过度重复的清单 |
| 制作有效 | 有效实验率、超预算比例、发现至验证耗时 | 是否帮助更快完成验证 |
| 经营有效 | 已测试版本的预注册通过率、成本/收益及不确定性 | 能否支持经营方向的结论 |
| 反馈质量 | 放弃原因覆盖、样本/版本完整率、未测比例 | 能否训练或校准下一版 |

选择率、浏览量、用户点赞只作为使用体验指标，不能作为唯一正确性标签。新算法把项目放在第1位会影响选用；不控制曝光就可能只学会重复自己。

## 7. 权重和阈值如何调

阶段0：使用公开、固定、可解释的启动参数，跑通输入与计算，做合成数据测试。阶段1：积累真实周快照和结局，在验证窗口用小范围参数网格比较，锁定最终测试集。阶段2：足够多、可比且有代表性的内部测试结局后，评估简单可解释模型是否优于规则；仍保留硬资格和组合层。

先调最有影响的少数参数：市场窗口/覆盖线、口碑精度要求、制作预算、D/P/F权重。不能对几十个阈值反复试到历史成绩好看，再把同一数据当独立验证。记录试验次数、全部配置和失败结果；效果不稳定时保留简单基线。

上线不采用随意固定“至少100条就能训练”。检查事件数、类别分布、相关性、缺失、市场代表性以及性能区间；确定性门槛误入应接近零容忍，排序提升需在多个时间/玩法子集出现，且不以更低覆盖和更少推荐为代价。

## 8. 影子运行与实际试验

先影子运行：旧方案和新方案同时生成但不自动扩大制作投入，对照入选/未选差异和人工复核成本。建议先观察若干完整标签周期，具体长度由数据成熟速度决定。没有真实回测，本次不声称新算法已经胜出。

在所有硬资格通过的候选中，可设少量明确标识的探索名额，对接近边界、数据不足但可低成本补证的项目进行标准化验证；保留入选概率和分配条件。探索不放宽IAA门槛。是否进行随机分配属于后续实验设计，当前没有启用任何真实试验或任务。

由于自主选择、能力和投入不同，内部结局不是随机样本。不可把未被选用当失败；除非记录并满足可识别的曝光/选择概率等条件，不随意使用逆倾向加权宣称已消除偏差。优先采用统一试玩协议与可比对照。

## 9. 发布与回滚

一个推荐版本包括feature_schema、metric_definition、profile、rule、taxonomy、model、prompt、evidence_set、entity_map、scenario_set、report_revision。所有重要变更先产生新版本，再并跑比较。发现源口径变化、引用缺失、身份误合并、IAA误入或异常高推荐翻转率时，暂停受影响队列或回滚到已验证版本，保留未受影响查询与手工记录。

## 10. 一份可执行的比较试验登记

| 字段 | 预先记录内容 |
| --- | --- |
| 研究问题 | 在相同推荐容量下，是否提高后续需求命中，且未明显损失提前发现和候选覆盖 |
| 主比较 | V2.2对比V2.1完整输入门槛与最新单榜排名；等权/在榜率为辅助基线 |
| 候选与排除 | 同市场、同时间可得候选；相同资格与组合约束；完整保存排除原因 |
| 主指标 | 全部推荐的需求成立率，配结局覆盖、缺失边界和填充率 |
| 次指标 | 提前发现天数、玩法覆盖、有效实验率、复核工时、经营结果另评 |
| 参数搜索 | 只在验证窗尝试登记的少量候选；记录尝试次数，不看最终测试集调参 |
| 不确定性 | 对同一历史切点两算法结果做配对比较；按时间块与产品/家族相关结构估计波动 |
| 上线标准 | 先由业务定义可接受提升幅度、成本和覆盖容忍度；再在时间外测试检验，不事后选择标准 |
| 若无提升 | 保留较简单/低成本方案，公布未胜出的结果与可能原因；优先修复数据覆盖或样本偏差 |

独立周/产品数量不足以形成稳定区间时，报告点估计和具体不确定性来源，不输出显著性结论。对于被同时推荐的同一产品，两个算法共享同一结局，不重复当作两个独立成功事件。

## V2.2：缺失情况下也要评价效果

保留时间外评估及标签未知边界。新增分层：推荐层级、输入覆盖、来源可得性、连续缺日长度、平台/市场、新旧产品。测试已知完整样例上的蒙蔽恢复，只能证明计算合理，不代表真实准确性。

| 回放情景 | 检查重点 |
| --- | --- |
| 独立随机删字段/日期 | 基础范围与推荐变化 |
| 整来源、整平台持续不可用 | 系统性不可得，不只模拟随机漏采 |
| 只在高热时能抓到数据 | 选择偏差及虚假增长 |
| 连续掉线后恢复、权限变化 | 有效缓存、旧信息和新available_at分开 |
| 缺负面评价或高成本材料 | 已知约束不消失，不能因为数据变少更容易直接开工 |
| 高覆盖但全部转载/热评 | 不能把冗余和偏差算独立支持 |

比较V2.1完整输入门槛、V2.2范围+分层、简单榜单基线，以及去掉探索名额的V2.2。缺失时不把剩余指标重新加权作为生产默认，但可作为明确标注的实验基线。对比同市场、同候选、同截止日；真实测试预算一致。

分别报告候选诊断覆盖、验证名单填充率、线索升级率、补证任务完成率与耗时、真实Precision@K/持续需求、原型测试完成率、停止损失和单位有效实验成本。范围宽度只是信息不确定性的代理，不能替代预测效果；综合范围不具备已校准置信覆盖，不能声称95%命中。

补齐同一时点原本缺失的信息可用于离线检查范围是否覆盖完整规格结果；该检查不是对真实未来成功的区间覆盖测试。后补信息不得泄漏进入历史当时推荐。评估还要报告未完成实验/未知结局，不能只看已成功的项目。

探索的收益和风险需要用实际补证与测试结果检验。后续如增加期望信息价值、先验插补或学习排序，先登记模型、缺失机制假设、训练样本、校准与退出条件，再做时间外对照。新可靠信息可能使推荐下降，这应算合理纠正，而不是稳定性错误。
