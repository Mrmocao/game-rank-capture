# 玩家评价与舆情设计

## 1. 关注度、口碑、证据质量三个轴

关注度回答多少内容在讨论、讨论是否增加；口碑回答人们对哪些体验满意或不满意；证据质量回答样本是否充分、覆盖是否稳定、结论是否能追溯。三者分别展示，不做“讨论越多→好评越高→值得开发”的连锁推断。

评价范围含商店评分与文字评价、公开社区体验帖、公开论坛、视频/直播下的体验讨论、可公开访问的内容评论、授权内部试玩反馈。媒体与广告主自述作为背景材料，不能冒充玩家独立体验。开发者回复是回复对象，不计入玩家正负评价分母。

计划覆盖中文和目标海外市场语言。各来源是否提供搜索、历史、完整评论、可保存文本及地域字段，须后续验证；拿不到就保留覆盖缺口，不用空白数据宣称零讨论。

## 2. 每条内容最小记录

来源ID/来源族、来源内容ID、原始定位、产品/版本归属及不确定性、原文或授权摘录、原文语言、译文、发布时间/编辑时间/首次采集时间、所述版本、可用地区、内容类型、作者在来源内的去标识ID、星级（如果存在）、互动观测值及观测时间、引用/转载关系、去重簇、品牌/商业合作已知标签、疑似异常标记、授权和保存范围。

AI派生字段另存：总情感、方面情感、主题、具体问题、玩家期待、可改进点、推断依据片段、无法判断原因、标注版本和人工纠正。翻译不覆盖原文。作者跨平台身份默认不合并，避免把昵称相同误认为同一个人。

## 3. 统一主题分类

| 一级主题 | 二级观察项 | 推荐用途 |
| --- | --- | --- |
| 核心玩法 | 理解成本、操作反馈、爽点、策略深度、随机性、重复可玩 | 确认可保留的需求与机制 |
| 难度和节奏 | 首局、难度曲线、卡关、失败惩罚、等待与耗时 | 设计首局与关卡验证 |
| 广告体验 | 激励广告、强制插屏、频次、打断、广告后奖励兑现 | IAA体验设计及争议检查 |
| 内容供给 | 重复关卡、新内容、目标持续性、完成后的空虚 | 判断持续制作成本 |
| 真实性 | 广告和实机不一致、截图误导、承诺未兑现 | 获客素材验证与复核 |
| 稳定性 | 崩溃、卡顿、发热、存档丢失、兼容性 | 确认问题能否通过实现改善 |
| 视听和使用 | 美术辨识、音效、UI可读、操作、无障碍 | 评估表现成本与改善空间 |
| 服务与其他 | 更新、客服、网络、社交体验、本地化 | 评估运营负担和地区差异 |

一条评论可以含多个主题；同一条中“玩法好玩但广告过多”分别标注玩法正面、广告负面，整体允许“混合/无法判断”。主题频次不可直接相加当作评论总数。讽刺、引用、跨语言歧义、未体验者推测应标未知或复核，不能硬分正负。

## 4. 指标口径

| 指标 | 建议定义 | 边界 |
| --- | --- | --- |
| 评分显示值 | 来源原生评分、尺度、地区、版本/设备范围、观测日 | 不视为同一算法的跨店均分 |
| 星级样本好评率 | 4～5星数 / 同一范围有效1～5星总数 | 需有分布；只有均分不能推导；只抓到部分评分则称样本好评率 |
| 正面反馈占比 | 正面 /（正面+负面+中性） | 无法判断和混合单列；必须同时展示全部处理量和可判断分母 |
| 方面负面率 | 该方面负面条数 / 对该方面可判断条数 | 不把没有提及该方面的评论当中性 |
| 去重提及量 | 指定来源范围和窗口内的独立内容簇数 | 是内容量，不是独立玩家数；归属模糊内容不计主体值 |
| 来源内参与者数 | 同一来源有效作者ID去重数 | 跨来源仅显示分项，不直接求和为全网人数 |
| 提及环比 |（本7日量 / 前7日量 - 1）×100% | 同源同检索同覆盖；基期0显示新出现；两期0显示无观测内容 |
| 负面变化 | 本窗负面率 - 前窗负面率，单位百分点 | 显示两期样本量，不写成百分比增长 |
| 独立证据族数 | 排除转载同源后的根来源族数量 | 十次转发同一视频不是十个独立验证 |
| 互动增长 | 同一内容两个观测时点的计数差 | 累计点赞截图不能冒充当日新增；减少可能是回撤，不强制置0 |

默认窗口为1/7/28/90天及自上线累计；周精选用完整周与前一完整周对照。页面上的“数据日期”表示截止日，旁边显式注明窗口。来源新接入、检索词改变、接口仅返回热评、分页不完整时，标记口径断点并暂停直接环比。

评分数不等于文字评价数，来源展示计数不等于本系统抓到的条数。即使文案评价没有变化，评分展示值也可能因为来源机制而变化。Apple 官方说明评分按地区呈现，发布新版本可重置概要评分而不重置文字评价；Google 官方区分近期加权展示评分与历史平均。由此本设计要求独立保存评分口径和重置/算法变化信号，而不直接平均两家分数。详见文末来源。

## 5. 抽样与质量

广度层保留全量可得计数和覆盖摘要；深度层在允许的内容范围内按日期、来源、星级/倾向、版本分层抽样。记录每层总体规模（若可得）、抽样方法、样本量、已知偏差；总量未知则不宣称代表性。只采高赞/热评的样本不得用于全量正面率估计。

V2.2以样本口径、独立内容、Wilson范围和来源/版本集中情况判断玩家证据，不按固定条数直接决定精选资格。默认区间宽度不超过30个百分点用于“重点验证”层级，缺样本或区间较宽时仍可条件推荐；这是待校准精度要求。缺失不填中性分，具体范围与分层见14。重大事件、身份、IAA及需求依据另行判断。

重复文本、短时激增、单作者集中等只触发“疑似异常”，不得由AI直接断定刷量或删掉原始内容。展示纳入/排除两种敏感性结果和排除理由；原始证据保留，人工可纠正。百分比附分子/分母，正式版可给区间但不能以区间制造代表性。

## 6. 舆情事件卡

事件卡含名称、事件类型、开始/结束或持续中、影响产品版本/市场、起点线索、热度与情感变化、主要主题、原始来源链、官方回应、已知事实、推断、反对证据、下一步、复核状态。状态为待复核/已确认影响/已排除/持续观察/已解决。

初始异常规则示例：固定来源集合内提及至少100、环比至少100%，且负面占比上升至少15个百分点，生成复核任务；所有阈值可配置，不当作行业定律。新来源接入或采样改变时不触发该规则。

负面可分为可改进的体验问题、重大真实性/服务问题、与核心机制无关的短期故障。AI应说明玩家喜欢的机制与抱怨的实现部分，不能把某款游戏的争议直接投射到整个玩法。事件未复核时可以进入观察提醒，不进入正式精选；复核完成后按影响决定释放、降低优先级或暂不匹配，记录有效期。

## 7. 原型实现范围

当前原型可按产品、日期、情感、主题、来源筛选手写样例，事件可下钻负面摘录，证据弹窗展示来源族/时间/标注；统计口径可查看。聚合数字为独立演示夹具，摘录不是其完整分母。生产环境必须以可追溯样本集合实时或离线计算，不能沿用这些固定数字。

## V2.2：缺评价与小样本不阻断整个推荐

没有可比玩家样本时，P维为[0,100]未知范围，依据其他材料继续给条件或线索推荐。口径可比的小样本使用Wilson上下界；区间过宽影响“重点验证”层级，不再一律排除。可比但只有10条与100条都算输入存在，样本精度在区间中体现，不能用覆盖100%暗示精确。

来源权限、过期、冲突、热评抽样各自保留原因。定性主题仍可辅助调查，不能伪装成全体玩家比例。已确认重大事件不会因评论接口掉线消失。此项覆盖前文及04中V2.1完整轨道的旧限制，详见14。
