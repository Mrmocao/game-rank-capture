# PoC、排期、成本与验收

本章给出可执行启动方案。排期以2名后端/数据工程师、1名前端参与管理端、0.5～1名研究运营为估算前提，不能视为已有团队承诺；凭证审批或采购时间另计。

## 1. 第一个工作包：7日来源验证

第1～2日建立SourceRegistry、最小任务记录、证据目录和样本结果格式；每平台选10个ID明确的产品，包含IAA声明样例、明确IAP反例、同名/跨平台歧义、低评论量/无评论量案例。总样本约40个平台实体，覆盖四国Google Play展示差异。来源许可不明时先人工核验，不能为跑满样本绕过限制。

第1～7日按计划时点重复检查核心榜源。每次保留实际URL、地区/设备、来源日期/抓取时间、是否匿名、条数/连续名次深度、重复与缺口、响应/限制及核验人。7天试运行只能说明一周稳定性，不能证明长期SLA；上线后累计28日再复评。

| PoC | 具体问题 | 通过条件 | 不通过后的上线方案 |
| --- | --- | --- | --- |
| Apple元数据 | 指定中国市场ID是否返回稳定字段 | ID/字段类型/日期/来源验证通过，10个样例可复核 | 详情页或授权元数据 |
| iOS榜单 | 公开页/RSS实际覆盖多少名 | 每个方案独立登记深度，排名与人工页面一致，无虚增 | 上线真实Top25/其他深度；Top100采购补缺 |
| GP四国榜单 | 实际市场/设备/榜型是否可确认，深度多少 | 四国分别验收；不接受只换URL参数的截图 | 未过的市场显示缺口；授权榜/人工 |
| GP详情 | 评分、计数、下载档位、广告/IAP语义 | 源原文与标准字段对应明确；缩写不伪精确 | 原文展示+待映射，不进数值分析 |
| 抖音趋势 | 匿名能否取得榜项、ID、日期 | 三种榜分别登记字段和定义；不是只验证页面打开 | 官方/第三方授权或人工材料 |
| 微信公开来源 | 出处、日期、榜类型、深度可信否 | 有原始出处，人工抽查；图表OCR错误可追溯 | 按篇收录；每日Top100另寻授权 |
| 评论样本 | 是最新还是精选，能否按时窗更新 | 逐源存采样协议与真实可得条数；去重/编辑处理 | 定性样本或人工，不计算总体正向率 |
| 材料与AI | 引用、类型、未知及权限是否正确 | 50份允许材料抽查；关键事实无无依据写入 | 暂停该字段自动写入，AI仅草稿 |

试运行目标：对已明确承诺的范围，7日计划任务有效完成率≥95%；每日任务的7日样本实际意味着应7/7通过，不能靠增加重试任务做大分母。HTTP200但字段解析失败、地区错或覆盖未达承诺不算成功。按单源/市场分别验收，不用平均值遮住微信完全缺失。

排名/稳定ID属于关键字段，PoC抽查和已标注黄金样本要求零错误；这只是样本验收，不宣称全市场零错误。AI引用支持率可设≥95%的试运行目标，IAA/身份等高风险资格仍走确定性校验/复核，不被平均准确率豁免。

## 2. 后续4～6周推进顺序

1. 第1周：完成上述PoC与缺口清单；决定哪些源按部分覆盖上线，哪些需要授权样本；确定来源预算。
2. 第2～3周：上线任务/证据/身份/榜单/基础档案，支持指定日期、覆盖状态、受控CSV和人工导入；搭建评论采样协议与IAA核查表。
3. 第3～4周：接入可见评价、材料白名单、AI有引用抽取、人工复核与字段补证；每周实际深研少量产品，先测工作量。
4. 第5～6周：接V2.2推荐，冻结证据生成周报；做整源掉线、日期缺口、部分榜、政策删除、跨平台歧义等演练；已取得许可的供应商再补缺。

最小可用版不以“30来源全部接通”为前提。要求每个核心平台至少有明确的观察/导入路径，清楚展示可得深度和未接通能力；若业务硬要求全平台连续Top100，未满足部分必须列为发布阻断条件，不能仅靠界面展示占位通过。

## 3. 成本模型：先量工作量，再报价

启动预算示例假设关注池300、长尾1,700个平台实体：详情日请求约300+1700/7≈543，加上新增实体和重试；榜单请求量取决于榜型/市场/分页，不等于100名×100次请求。若10条榜每条1～5页则约10～50请求/日，属于计划假设，不代表10条源都可用。

评论若300个关注实体各1～3个允许的页面，约300～900请求/日，新增样本可能远小于网页条数；所有请求受来源限额而不是预算强行拉满。发现搜索先设50查询/日、YouTube参考检索20查询/日作为内部预算，实际运行要读取官方/供应商当前额度，未开通则不执行。

人工核查假设每周10～20个重点版本、每个试玩15～30分钟，约2.5～10小时；加上记录、IAA查证、版本/身份冲突和周报复核，先预留每周8～16小时并实测。复杂产品自动转更长任务，不能为了效率跳过关键证据。

月成本 = 运行计算与浏览器小时 + 对象存储/流量 + 搜索/API费用 + AI输入/输出token费用 + 人工时间 + 购买数据费用。AI只处理新增/修改且去重后允许的材料；榜单数值无需每次调用模型。按实际tokens和选定模型单价计算，不在未选模型前承诺金额。

粗存储测算：每天3,000个可保存响应、压缩后平均100KB，约0.3GB/日、9GB/30日；不含视频、索引/副本。这个估算须以PoC实际平均字节修正；不能因此给所有来源统一30日保留。视频默认链接，截图/原始文档按许可策略限额。

## 4. 采购只问可验收的事情

向候选供应商索取7日样本与字段字典，包含：目标平台/国家/设备、榜类型及原始出处、稳定ID、日期与更新时点、实际TopN、分页、历史起点与缺口、评论采样方法、是否估算、修订/删除策略、API/导出权限、内部展示/AI分析/报告再分发权、配额/SLA和计费。

DataEye官方页面已说明提供API与广告情报服务，可列为买量数据候选；不据此假设它提供微信官方人气榜或真实竞品收益。其他商店/小游戏供应商逐一验证再登记，不在当前文档中写未经确认的覆盖或报价。

采购优先级：①关键平台可靠日榜与身份；②连续可比的评论样本；③素材/买量观察；④经营估算。公开源的Top25与供应商Top100先并行，不直接拼接历史；即使数据一致也要记录相同根来源，不能当两份独立成功证据。

## 5. 必做验收案例

| ID | 输入或故障 | 必须输出的行为 |
| --- | --- | --- |
| C01 | 目标100、仅看到1～25名 | partial；实际25；未见游戏不判Top100榜外 |
| C02 | Top25中已见第18名 | 保留rank=18；可用该日已知位置；不按25缩放分数 |
| C03 | HTTP200但空列表/登录页 | 解析异常或access_blocked；不存完整0条榜 |
| C04 | 昨天抓取失败，今天成功 | 昨天missing；今天事实不得补造昨天 |
| C05 | 来源有指定日期历史接口 | 验证source_date后可补历史，available_at仍为今天 |
| C06 | 同名不同包名/小游戏ID | 分实体；自动提出关联而非合并 |
| C07 | 只显示Contains ads | IAA仍待核；有IAP标记则按版本保留反证 |
| C08 | 老版纯IAA、新版出现内购 | 新版资格转冲突/不匹配；旧版本事实保留 |
| C09 | 评分计数“164万”但只见6条评论 | 分别存缩写评分量与6条样本，不产生164万文字评论 |
| C10 | 精选评论全正向 | 输出样本主题；不宣称全体100%好评 |
| C11 | 评论被修改或展开区重复 | 修订/去重；不重复增加正负样本分母 |
| C12 | 扩大查询或来源导致内容翻倍 | 新panel_version/覆盖断点；不直接标热度翻倍 |
| C13 | 五站转载一份机构报告 | 同一根来源族，不计5份独立证据 |
| C14 | 第三方买量榜名次很好 | 投放信号单列，不能独立通过玩家需求门槛 |
| C15 | 429/403/验证码 | 有限退避/停止/授权补缺，不换IP绕过 |
| C16 | AI超时或无引用输出 | 原始事实继续入库，增强字段unknown/草稿 |
| C17 | 替换数据供应商 | 原始系列独立；未经可比审核不拼上涨曲线 |
| C18 | source policy禁止分析或到期删除 | 不送AI/不算分；执行删除传播并标历史影响 |
| C19 | YouTube公开播放量可取得 | 默认原始展示/参考，不自动生成热度衍生指标 |
| C20 | 两worker同时完成相同任务 | 幂等提交、租约校验，只产生一次有效业务事件 |
| C21 | 一个平台长期缺失 | 该平台缺口独立显示，其他队列继续出报告 |
| C22 | 来源缺失让已知负面证据抓不到 | 既有有效约束保留，不能自动恢复正式推荐 |
| C23 | 正式合格项目不足5个 | 输出实际数量及线索/补证；不凑满或编造 |
| C24 | 用户查看2026-10-01历史日期 | 取该日有效事实；区分当时已知与后补版本，不返回最新榜冒充历史 |
| C25 | 租户A导入私有测试或供应商材料 | 租户B无权读取、检索或通过AI摘要间接获取 |

## 6. Codex开发任务边界

先实现：来源注册与策略 → 幂等任务与证据 → 通过PoC的连接器 → 身份/覆盖/评论样本 → AI草案 → V2.2特征与周报 → 运维质量页。每个连接器先小样本fixture回放，再源准入环境少量验证；未经验证的候选地址不得默认开启生产定时任务。

此次交付提供方案、来源登记、201行字段映射、配置样例与验收清单；没有运行真实采集器、没有创建定时采集任务、没有获取平台凭证、没有接Java/MySQL、也没有修改线上V2.3原型。上线前应运行本章案例并另存实际验证报告。
